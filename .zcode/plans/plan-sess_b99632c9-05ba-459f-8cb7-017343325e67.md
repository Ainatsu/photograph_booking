# 平台规则 RAG + agent 规则查询意图/工具 实施计划

## 目标

将 `docs/rules/*.md` 切分为 chunk 灌入项目原生 RAG 库(pgvector),并为 agent 新增意图 `rule_query`(规则查询)+ 只读工具 `search_platform_rules`,prompt 约束 agent 基于检索结果回答规则问题。

## 核心方案:复用原生设施,零新表零迁移

规则 chunk 以 `resource_type="platform_rule"` 存入现有 `ai_resource_documents`,向量存 `ai_resource_embeddings`——Postgres 上 `vector(512)` 列 + HNSW 余弦索引已由既有迁移建好(与本地 BGE 512 维一致),SQLite 开发环境自动降级为 `embedding_json` + Python 余弦(约 150 个 chunk,无压力)。嵌入生成复用 `ai_embedding_service` 的 provider 体系(mock / local_bge / openai_compatible)与 `sync_resource_embeddings` 的批量、哈希跳过、pgvector 写入逻辑。

## 实施步骤

### A. 数据层与 ingestion

1. **`backend/app/core/config.py`**:新增 `AI_PLATFORM_RULES_ENABLED=True`、`AI_PLATFORM_RULES_TOP_K=5`、`AI_PLATFORM_RULES_DIR`(默认指向仓库 `docs/rules`)。
2. **新服务 `backend/app/services/platform_rule_service.py`**:
   - **Chunker**:解析 markdown——按 `- 规 XX-n:` 规则条目切分(规则块含其续行与子条目),每个 chunk 的嵌入文本前置「文档标题 + H2 小节标题」上下文;跳过 `README.md`(元文档);规则 ID 稳定作为 resource_id(如 `order-payment-rules#OR-11`)。
   - **Upsert**:按 `(resource_type, resource_id)` 唯一键,content_hash 变更检测;`owner_user_id=0` 哨兵(该列 NOT NULL);payload 存 rule_id/doc/section/source_file;删除已不存在的规则 chunk(仅限 `platform_rule` 类型)。
   - **检索 `search_platform_rules(db, query, limit)`**:`query_embedding()` → Postgres 走 `pgvector_candidate_scores(resource_types=["platform_rule"])`;SQLite 回退为加载规则行 + `cosine_similarity()` 内存排序;返回 top_k(含 rule_id、小节、原文、得分)。
3. **`ai_resource_index_service.py` 防误删加固**(关键):`rebuild_ai_resource_documents` 的 `existing_query` 增加 `.filter(resource_type.in_(DOCUMENT_KEYS_BY_TYPE))`,使全量重建不再清除规则行;加回归测试。
4. **`ai_embedding_service.py`**:`pgvector_candidate_scores` 的类型白名单(第 457-460 行)加入 `"platform_rule"`。
5. **触发路径**:
   - `backend/app/main.py` lifespan 中调用 `ensure_platform_rules_indexed()`(哈希未变则跳过,幂等廉价),随后复用 `sync_resource_embeddings` 补嵌入;
   - 新增 CLI `backend/scripts/sync_platform_rules.py`(支持 `--force`);
   - `docker-compose.yml` 为 backend 容器挂载 `./docs/rules` 只读卷(规则文档需进容器)。

### B. 工具注册与执行(先做工具,决策层 chat 意图即可用)

6. **`ai_agent_decision_contracts.py`**:新增 `SearchPlatformRulesInput`(query 必填 + limit,`extra="forbid"`,仿 `SearchWebInput`)。
7. **`ai_tool_policy_service.py`**:`TOOL_REGISTRY` 注册 `search_platform_rules`——READ_ONLY / ConfirmationPolicy.NONE / `llm_selectable=True` / idempotent / audit_fields=("query","limit");`build_tool_catalog` 按 `AI_PLATFORM_RULES_ENABLED` 开关(仿 `WEB_SEARCH_ENABLED` gate)。
8. **`ai_agent_decision_service.py`**:read_tool 集合(现仅 `get_shoot_context`/`search_web`)加入 `search_platform_rules`;可选加确定性 fast-path。
9. **`ai_agent_decision_prompt.py`**:新增硬规则「用户询问平台规则(退款、改期、审核、限额、合同条款等)时,调用 search_platform_rules,不得凭记忆回答」;`DECISION_PROMPT_VERSION` v3→v4。

### C. 意图 rule_query(用户明确要求;供旧路由/规则模式确定性触发)

10. **`ai_intent_prompt.py`**:`INTENT_PROMPT_VERSION` v4→v5;新增 `rule_query` 定义、边界规则(「咨询退款政策/审核规则」→ rule_query;「我要预约」→ booking_flow;「找摄影师」→ resource_search)与正反例。
11. **`ai_agent_contracts.py`**:`LLMIntentCandidate.intent` Literal 与 `INTENT_POLICIES` 加 `rule_query`(route="rule_query", requires_confirmation=False)。
12. **`ai_orchestrator_service.py`**:`recognize_intent_by_rules` 增加关键词谓词(规则/政策/退款/审核/限额/定金/改期政策等)返回 rule_query。
13. **`ai_agent_decision_service.py`**:`DECISION_ELIGIBLE_INTENTS` 加 `"rule_query"`;`_INTENT_TO_TOOL` 映射。
14. **`ai_service.py`**:意图 if/elif 增加 `rule_query` legacy 分支(直接执行同一检索,无需决策层)。

### D. 结果注入与 prompt 约束(满足"PROMPT 约束 agent 使用 RAG 返回值回答")

15. **`ai_service.py` read_tool 执行分支**(仿 `search_web`/`get_shoot_context`,约 3891-3913 行):第三分支调用 `search_platform_rules` 并暂存结果。
16. **结果 prompt 常量**(放 `ai_prompts.py`,与 `CHAT_NO_PLATFORM_DATA_PROMPT` 并列):「以下是 search_platform_rules 检索到的平台规则原文片段。回答必须基于这些片段,引用规则编号(如 规 OR-11);若未命中,明确说明未找到对应规则,不得凭记忆编造数值或政策」。在 `_build_provider_messages` 的 extra_system_prompts 注入,并**计入 `has_platform_context`**(避免误触发反编造兜底把规则引用剥掉)。

### E. 测试(仿 `test_agent_web_search_regression.py` 模式)

17. `test_platform_rule_ingestion.py`:chunk 解析(规则 ID、子条目聚合、README 跳过)、upsert 幂等、失效删除、**全量重建不清除规则行**(针对步骤 3 的回归)。
18. `test_platform_rule_search.py`:mock provider 下检索命中、空库返回空、top_k 生效。
19. `test_agent_platform_rules_tool.py`:输入合约、工具授权(read_only 无确认)、read_tool plan、决策 prompt 版本提升与路由引导、intent Literal/policies/规则识别器、legacy 分支 grounding prompt 注入。
20. 回归:`test_ai_*` 与 `test_agent_*` 对照 HEAD 基线(既有约 22 个失败,只要求无新增失败)。

## 验证方式

- 新增测试全绿,既有测试对比基线无新增失败。
- 手动验收:启动后端,向小龟J问「订单超过 24 小时取消能退多少钱?」——应触发 `search_platform_rules` 并按「规 OR-11」回答 90%/50%/0% 退款梯度;问无关问题(如「推荐个上海摄影师」)不触发该工具。

## 不做的事(明确排除)

- 不新建表、不写新 Alembic 迁移(复用既有 pgvector 列);
- 不把规则混入摄影师混合检索的 `REFERENCE_KEYS`(规则检索独立通道);
- 不做 agent workflow 模板(单步只读检索,workflow 属过度设计);
- 前端无改动(无 intent 枚举在前端)。
