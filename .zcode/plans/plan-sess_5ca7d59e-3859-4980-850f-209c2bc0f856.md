# 新增 Agent 能力【赏析作品】

## 设计概述

复用现有两条成熟通道（与文生图/以图生图、创作灵感完全同构）：

- **显式选择（确定性）**：前端新增「赏析作品」能力 chip，发送时在消息 payload 上附带 `appreciation_request: true`，后端跳过意图分类器、直接强制进入赏析流程（镜像 `generation_request` 的强制意图模式，`ai_service.py:3543`）。
- **意图识别（自然语言）**：用户带图输入"帮我赏析/点评这张照片"时，规则识别器命中新增关键词返回 `image_analysis` + 子意图 `work_appreciation`；分发层再用同一关键词兜底，覆盖 LLM 分类器路径。
- 赏析回复 = 模型在「赏析 skill 系统提示词」约束下生成的自由 markdown 文本，走普通聊天气泡渲染，无需新卡片。

## 后端改动

### 1. `backend/app/services/ai_vision_service.py`
新增常量 `APPRECIATION_SYSTEM_PROMPT`，内容为用户提供的完整赏析 skill 文本（"你是一名摄影作品赏析者，而不是图像内容描述器……"）。

### 2. `backend/app/services/ai_orchestrator_service.py`
- 新增 `_is_work_appreciation_intent(text)` 关键词匹配：`赏析 / 点评 / 品评 / 好在哪 / 为什么好` 等短语。
- 在 `recognize_intent_by_rules` 的通用 `has_image` 兜底（第 223 行）**之前**插入规则：有图且命中关键词 → `AgentIntent(intent="image_analysis", sub_intents=["work_appreciation"], route="vision", confidence=0.9)`。

### 3. `backend/app/schemas/ai.py`
`AIMessageCreate` 新增 `appreciation_request: bool | None = None`。

### 4. `backend/app/api/v1/ai.py`
`create_ai_message` 把 `data.appreciation_request` 透传给 `send_ai_message`。

### 5. `backend/app/services/ai_service.py`（核心）
- `send_ai_message(..., appreciation_request: bool | None = None)`；写入 `user_metadata`（镜像 3170 行 generation_request 的做法）；加入 `deterministic_entry` 判定（3473 行），并镜像 3188 行 active_task 分支对 generation_request 的排除。
- 意图强制：`elif appreciation_request:` → `image_analysis` + `sub_intents=["work_appreciation"]`，confidence=1.0，parser="rules"。
- 意图识别后计算：`is_appreciation = intent.intent == "image_analysis" and ("work_appreciation" in intent.sub_intents or _is_work_appreciation_intent(content))` —— 关键词兜底同时覆盖规则与 LLM 两条分类路径。
- 视觉调用块（3796 行）：条件扩展为「标准视觉分析 **或** is_appreciation 且有图」；is_appreciation 时 `extra_system_prompts` 用 `APPRECIATION_SYSTEM_PROMPT` 而非 `VISION_SYSTEM_PROMPT`，**不**做 `normalize_vision_analysis` / `_apply_vision_slots`，保留模型原始文本为 `appreciation_reply`。
- 无图守卫：is_appreciation 且无图片附件 → 返回引导语"请先上传要赏析的摄影作品"。
- 分发链：在现有 `image_analysis` 分支（4181 行）之前插入 `elif intent.intent == "image_analysis" and appreciation_reply:` → 新 helper `_appreciation_agent_result(provider_result, content, attachments)`，content 为模型赏析文本，metadata 带 `tool_calls: [{tool: "appreciate_image", status: "success", ...}]`（镜像 `_vision_agent_result` 的结构）。

### 6. `backend/app/services/ai_intent_prompt.py`
`image_analysis` 意图描述补充「赏析作品」示例（如"帮我赏析这张照片为什么成立"），让 LLM 分类器也倾向正确路由。

## 已知边界（按现有模式接受，不额外处理）

- 赏析后的追问（"再说说构图"）走普通聊天路径，依赖会话历史延续语境 —— 与现有 `image_analysis` 行为一致。
- 多图可一起上传赏析，不设上限（沿用现有全局附件上限）。
