# 修复：compound_workflow 被模型 resource_search 静默降级的问题

## 背景（已诊断的根因）

agenttest8 的「帮我寻找森系的作品然后用它们创建灵感」被规则分类器正确判为 `compound_workflow`（0.96 置信度），但模型分类器（mimo）报了 `resource_search`。`_reconcile_hybrid_intent`（backend/app/services/ai_intent_classifier_service.py:158）中保护 compound_workflow 的分支只在 `model_intent == "create_inspiration_flow"` 时触发（L182）；模型报 resource_search 时无任何保护，L205 `return model_intent` 直接采纳模型结果，编排拆分丢失。且 `intent_classifier_v5` prompt 的候选标签里根本没有 `compound_workflow`，模型永远无法自己给出正确答案。

## 改动

### 1. `_reconcile_hybrid_intent` 增加规则侧 compound_workflow 优先守卫（核心修复）

文件：`backend/app/services/ai_intent_classifier_service.py:175-201`

将现有的 create_inspiration_flow 补救分支扩展为：**只要规则判定为 `compound_workflow` 且模型没有同样给出 `compound_workflow`，就保留规则的 compound_workflow**（模型侧无论报 resource_search、chat 还是 create_inspiration_flow，统一走该分支）：

```python
if (
    not has_image
    and (
        (rule_intent.intent == "compound_workflow" and model_intent.intent != "compound_workflow")
        or (model_intent.intent == "create_inspiration_flow" and (model_intent.slots.get("style") or model_intent.slots.get("styles")))
    )
):
    # 槽位合并 + apply_intent_policy("compound_workflow", ...)，返回 compound_workflow（parser="rules"）
```

保留原有的另一半子条件（模型报 create_inspiration_flow + 带 style 槽位、规则未判 compound 的隐式搜索场景），行为不变。理由：`_is_search_then_inspire_intent` 是确定性高精度规则（要求显式「创建灵感」类短语 + 显式搜索/风格语言、无图片），与 project_application 守卫同级，模型在无对应标签的情况下对复合指令的单步解读不应覆盖它。

### 2. 模型分类 prompt 增加 compound_workflow 标签（v5 → v6）

文件：`backend/app/services/ai_intent_prompt.py`

- `INTENT_PROMPT_VERSION` 改为 `"intent_classifier_v6"`。
- 在意图定义区新增：

  ```
  - "compound_workflow"：先搜索平台作品、再用结果创建拍摄灵感的复合指令（无图片附件）。例如："帮我寻找森系的作品然后用它们创建灵感"、"帮我找几张日系作品做成灵感"。
    注意：带图片附件的"创建灵感"仍是 create_inspiration_flow；单纯的"帮我找作品"没有创建灵感语义，仍是 resource_search。
  ```

- `LLMIntentCandidate.intent` Literal 已含 `compound_workflow`，契约层无需改动。

### 3. 同步测试断言

- `backend/tests/test_agent_platform_rules_tool.py:182`：`assert INTENT_PROMPT_VERSION == "intent_classifier_v5"` → 改为 v6。
- `backend/tests/test_ai_intent_classifier.py` 的弱断言（L414/L713 用 import 的常量）自动跟随，无需改。

### 4. 新增回归测试

文件：`backend/tests/test_ai_intent_classifier.py`（TestClassifyIntentHybridMode，沿用现有 fake provider 模式）

- `test_hybrid_model_resource_search_cannot_drop_compound_workflow`：provider 返回 `{"intent": "resource_search", "slots": {"styles": ["森系"]}, "confidence": 0.95}`，输入原文「帮我寻找森系的作品然后用它们创建灵感。」，断言最终 intent == `compound_workflow`、route == `workflow`、sub_intents == `["search_portfolio_item", "generate_inspiration"]`。
- `test_hybrid_model_chat_cannot_drop_compound_workflow`：模型报 chat 时同样保留 compound_workflow（验证守卫不依赖模型具体误判值）。
- 既有 `test_hybrid_no_image_inspiration_keeps_search_workflow`（L422）验证新旧分支合并后行为不回归。

## 不做的事（明确排除）

- **不开启** `AI_AGENT_WORKFLOW_SEARCH_THEN_INSPIRE_ENABLED`（保持 False）。修复后 intent 正确命中 legacy compound 分支（ai_service.py:4355），该分支本身完整执行「检索 + 创建灵感」两步；新 Workflow Runtime 的灰度开关属于独立发布决策。
- 不改 `_is_search_then_inspire_intent` 规则、不改决策层/tool policy。
