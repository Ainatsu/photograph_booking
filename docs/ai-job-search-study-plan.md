# AI 应用开发求职学习规划与简历评估

## 一、总体判断

当前学习路线是合理且有用的。

以现有摄影师预约项目、人工智能专业背景和简历基础，求职成都地区月薪 8k 左右的 Python 后端或 AI 应用开发岗位具有现实可能性，但最终结果仍取决于岗位市场、编程基础、项目掌握程度和面试表现。

真正重要的不是把所有章节“听完”，而是做到：

- 能用自己的话讲清楚项目业务
- 能定位关键代码并说明调用链
- 能解释设计原因和技术取舍
- 能承受面试官的连续追问
- 能独立完成基础编码题和小型功能

比较合适的个人定位是：

> 以 Python 后端能力为基础，能够把大模型接入真实业务的初级 AI 应用开发者。

## 二、推荐学习路线

### 阶段一：学习项目第 1～14 章

继续按照现有大纲学习到第 14 章，第 12 章 Agent 功能暂时跳过，后续单独深入。

这一阶段重点掌握：

- 项目整体架构
- 前后端职责划分
- 登录、JWT 与权限控制
- 数据库模型和迁移
- 套餐、企划和订单业务链路
- 支付、交付、验收和评价
- 消息、通知与 WebSocket
- 文件上传和对象存储
- 测试、Docker 和部署

先学习普通业务系统非常重要，因为 Agent 最终仍然需要调用传统业务能力：

```text
Agent
  ↓ 调用
业务工具
  ↓ 调用
Service
  ↓ 操作
数据库、订单、用户、套餐、企划
```

只有理解普通后端系统，才能真正解释：

- 为什么工具调用需要鉴权
- 为什么写操作需要用户确认
- 为什么模型不能自己生成资源 ID
- 为什么要使用幂等键
- 为什么 Agent 仍然需要 service 层

### 阶段二：单独深入 Agent 功能

建议为 Agent 功能建立独立学习目录：

1. Agent 功能解决什么问题
2. 普通聊天、RAG 和 Agent 的区别
3. 意图识别和路由
4. 槽位提取与多轮对话
5. Tool Calling
6. 工具注册和参数 Schema
7. 真实资源检索
8. RAG、Embedding 与混合检索
9. 上下文和历史资源引用
10. 任务状态管理
11. 写操作确认
12. 权限与风险分级
13. 幂等与重复调用
14. Action Log 与审计
15. 错误恢复和降级
16. Agent 测试与评估
17. 可观测性、成本和延迟
18. Agent 项目的面试表达

这一部分应当成为求职 AI 应用岗位的核心竞争力。

### 阶段三：学习项目相关“八股”

不要完全脱离项目背诵知识点，建议采用下面的学习方式：

```text
八股知识
  ↓
项目中在哪里使用
  ↓
为什么这样设计
  ↓
有什么缺点
  ↓
还能怎样改进
```

例如学习 JWT 时，除了知道 JWT 由 Header、Payload 和 Signature 组成，还应当能够回答：

- 项目登录后前端如何携带 JWT？
- FastAPI 后端如何解析当前用户？
- `token_version` 如何让旧 Token 失效？
- 为什么 JWT Payload 不能保存密码等敏感信息？

建议覆盖以下知识：

- Python 基础与进阶
- FastAPI、Pydantic 和依赖注入
- HTTP 与 RESTful API
- JWT、认证和授权
- SQL、索引、事务和隔离级别
- SQLAlchemy、N+1 和 Alembic
- Redis、缓存一致性和分布式锁
- 并发、异步、线程和进程
- Docker、Linux 和部署
- Git、测试与日志
- RAG、Embedding 和向量检索
- Tool Calling、Agent 状态和幂等
- 大模型幻觉、上下文、评估和安全

### 阶段四：进行模拟面试

模拟面试建议分为三轮：

1. 基础面试：Python、HTTP、数据库、缓存和并发
2. 项目面试：围绕摄影师预约项目连续追问
3. AI 应用面试：RAG、Agent、工具调用、评估和安全

模拟面试需要采用连续追问，而不是只回答一道孤立问题。例如：

```text
候选人：创建订单时使用了分布式锁。

面试官：为什么需要锁？
面试官：锁的粒度是什么？
面试官：如果 Redis 锁过期但数据库事务还没有完成怎么办？
面试官：只使用数据库约束可以吗？
面试官：你如何通过测试证明它解决了并发问题？
```

## 三、当前简历的优势

当前简历已经具有比较清晰的求职方向：

```text
Python 后端开发 / AI Agent 应用开发
```

主要优势包括：

- 人工智能本科专业与目标岗位相关
- 有计算机视觉算法实习经历
- 有一个业务链路较完整的全栈项目
- Agent 接入了真实业务，而不是简单聊天机器人
- 技术栈覆盖后端、数据库、测试、Docker 和前端
- 项目包含订单、支付、权限、消息、交付和争议处理等真实业务复杂度

Agent 项目中比较有价值的内容包括：

- 结构化工具调用
- Pydantic 参数校验
- 角色鉴权
- 写操作确认
- 风险分级
- 历史资源引用
- 幂等键
- Action Log 审计
- 避免模型虚构资源 ID

这些内容比仅仅写“调用大模型 API 完成聊天机器人”更有工程价值。

## 四、目前需要注意的风险

### 1. 简历描述越强，面试追问越深入

简历中写了独立完成移动端、Web 端、管理端和后端 API 的全栈开发，面试官可能继续追问：

- 数据库有多少张表？
- 最复杂的表关系是什么？
- 为什么套餐放在 JSON 中，而企划使用独立数据表？
- 订单如何避免时间冲突？
- 支付如何保证幂等？
- WebSocket 断线后怎么处理？
- Alembic 迁移如何保护已有数据？
- Playwright 覆盖了哪些关键路径？
- Docker 环境为什么需要 Redis 和 MinIO？

因此，简历中的每句话都需要能够承受至少三轮追问。

### 2. 不能只会描述，不会独立编码

AI 应用岗仍然是开发岗位，尤其是初级岗位。面试可能要求现场完成：

- Python 字典、列表、函数和类
- 文件处理
- SQL 查询
- FastAPI 接口
- Pydantic 模型
- 简单异步代码
- 哈希表、二分查找等基础算法
- 调用模型 API 并解析结构化 JSON
- 简单工具注册器
- 带任务状态的多轮对话流程

学习过程中需要保留“不看项目，自己重新实现”的练习。

### 3. 不要只投名称中包含 Agent 的岗位

纯 Agent 岗位数量相对有限，而且部分岗位希望候选人已经有较强后端、算法或大模型经验。

可以同时搜索：

- Python 后端开发
- AI 应用开发
- 大模型应用开发
- LLM 应用工程师
- Agent 开发工程师
- RAG 应用开发
- 智能助手开发
- AI 平台后端开发
- 知识库开发
- 工作流或智能体开发

## 五、简历调整建议

### 1. 删除所有占位内容

“证书与荣誉”模块目前仍有占位内容：

```text
奖项 / 证书名称 · 2025
奖学金 / 比赛荣誉 · 2024
```

正式投递前必须删除或替换。如果没有相关内容，可以直接删除整个模块。

### 2. 增加可验证的项目入口

条件允许时，可以补充：

- GitHub 或 Gitee 地址
- 在线演示地址
- 项目截图或演示视频
- 完整 README
- API 文档地址

面试官不一定会打开，但项目入口能够提高可信度。

### 3. 保证每个技术名词都能解释

简历中出现的每个词都可能成为面试问题：

```text
RAG 混合检索
多轮对话
结构化工具调用
风险分级
幂等键
Action Log
WebSocket
Alembic
Playwright
```

如果某项技术只是存在于项目中，但目前还不能解释，应先学透后再保留。

### 4. 增加可验证的项目结果

目前简历主要描述“做了什么”，以后可以补充真实、可证明的数字，例如：

- 后端接口数量
- 核心数据表数量
- 自动化测试数量
- 核心业务流程数量
- Agent 工具数量
- Agent 支持的资源类型
- 关键接口的性能优化结果

不能为了简历效果虚构数字，所有数据都应当能够通过代码、测试或运行结果证明。

## 六、关于成都 8k 和双休目标

对于成都地区应届本科生的 Python 后端或 AI 应用岗位，8k 是可以争取的目标，但不能保证。

主要影响因素包括：

- 当时的岗位数量和市场情况
- 学校和学历筛选
- 正式实习经历
- 项目能否真正讲透
- 基础编程能力
- 面试发挥
- 公司规模和业务方向
- 是否接受外包或驻场岗位

当前优势是项目复杂度高于普通课程项目；短板是正式实习经历较短，项目能力是否真正转化为个人能力仍需要通过学习和模拟面试验证。

双休会缩小岗位范围，但这是合理的求职要求。筛选岗位时需要关注：

- JD 是否明确写双休
- 是否存在大小周
- 是否长期加班
- 加班是否可以调休
- 试用期工资比例
- 社保和公积金基数
- 是否属于外包驻场
- 所谓 AI 岗位是否只是数据标注或简单接口搬运

不要只看月薪数字，也要关注实际工作内容和劳动条件。

## 七、每节项目学习的验收方式

每讲完一节，最好完成五件事：

1. 不看答案，用自己的话讲一遍
2. 说出关键代码文件和调用链
3. 回答“为什么这样设计”
4. 找出至少一个缺点或改进方向
5. 编写一个小功能或测试验证理解

例如学习完“摄影师接单、拒单、改期”后，应当能够回答：

- 为什么接单不能直接修改 `order.status`？
- 为什么接单时需要再次检查档期？
- 为什么改期申请不能立即覆盖原预约时间？
- 新候选时间为什么需要临时锁定？
- 系统如何防止申请人批准自己的改期申请？
- 接单、拒单和改期分别会记录哪些事件？

能够脱离讲义回答这些问题，才表示真正掌握了这一节。

## 八、最终目标

项目讲解、Agent 专题、计算机基础八股和模拟面试应当结合进行。

最终需要形成以下能力：

- 能完整介绍项目解决的问题
- 能画出关键业务调用链
- 能解释数据库和接口设计
- 能分析缓存、并发、权限和事务问题
- 能说明 Agent 如何安全调用真实业务工具
- 能独立完成基础 Python 和后端编码
- 能应对项目的连续追问
- 能诚实说明项目不足和改进方向

比较合适的求职定位是：

> 初级 Python 后端 / AI 应用开发，能够完成业务接口、数据库设计、Agent 工具调用、RAG 检索和工程化测试。
