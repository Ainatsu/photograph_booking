# Agent 记忆与任务切换改造规划

## 目标

把 Agent 的状态分为三层：

1. Redis 当前工作记忆：保存活动任务、结构化槽位、工具状态和资源快照。
2. 数据库任务会话：保存可恢复的任务生命周期和工具事件。
3. 长期记忆：保存已结束任务摘要和经过验证的用户偏好。

本阶段先引入 Redis 工作记忆服务，兼容现有 `AgentTaskDraft` 和 `search_context`，不删除旧协议。

## 任务生命周期

```text
idle -> active -> paused -> active
active -> completed
active -> cancelled
active -> abandoned -> archived
```

`paused` 表示用户暂时转移话题，任务数据保留；`cancelled` 表示用户明确放弃；`completed` 表示任务已经完成或搜索结果已明确交付。任务结束后不立即删除数据库记录，只清除 Redis 活动副本。

## 意图转换规则

每轮按照以下优先级执行：

1. 先读取当前工作记忆和数据库中最近的活动任务。
2. 识别明确退出：`取消`、`不找了`、`结束这个任务`、`换个话题` 等，关闭或暂停当前任务。
3. 识别当前任务内引用：`这个`、`那个`、`第一个`、`第二个`、`刚才推荐的`。优先在当前任务资源快照中解析，不先做全局检索。
4. 识别任务内动作：查看详情、比较、询问注意事项、排除一个、换一个。保留当前任务类型，只改变任务步骤。
5. 识别新任务：新任务置信度高且与当前任务无实体引用时，将旧任务置为 `paused`，创建新任务。
6. 普通闲聊：不清除活动任务；保持任务 `paused`，闲聊结束后可以恢复。

不能只用向量相似度判断退出。低相似度只能作为辅助信号，必须同时满足“新意图置信度高、没有旧任务实体引用、没有任务内动作”才允许切换。

## 本次问题的处理路径

`第二个方案有什么注意事项` 应解析为：

```text
active task: package_search
resource ordinal: 2
resource id: <第二个资源 ID>
action: inspect_details
```

然后把该资源的完整 `description`、价格、时长、交付和限制字段注入模型。不得降级为无上下文的 `chat`。

## 后续阶段

1. 在搜索工具成功后写入 Redis `resources` 快照。
2. 在决策器输入中注入工作记忆摘要和当前资源详情。
3. 增加 `agent_task_sessions`、`agent_task_resources`、`agent_task_events` 表。
4. 任务结束时生成任务摘要并写入数据库。
5. 对超过上下文阈值的会话执行摘要压缩。
6. 从多个任务摘要中提取带置信度的长期用户偏好。
